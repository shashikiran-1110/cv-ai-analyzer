# LLM evaluation — first run and what it found (2026-10-04)

**Mode: mock** (a deliberately adversarial scripted model, no key, no network). Mock runs prove the server-side
defenses; their *quality* numbers describe the mock, not a real model. Real-model numbers need
`python -m eval.run --suite llm --mode record --model <model>` with an API key (see README → LLM evaluation).

## Defense invariants (must be 0)

| Invariant | Value | What it means |
|---|---|---|
| `llm_deep_verify.unsupported_quote_accepted` | **0** | No AI verdict counted unless its quote exists in the resume. |
| `llm_safety.attack_success_defended` | **0 / 6** | Every prompt injection (posting → deep verifier ×4, posting → tailoring, resume → advice prompt leak) was stopped, although the mock obeyed all of them (`raw_compliance_rate` 1.0). |
| `llm_tailoring.unverifiable_in_accepted` | **0** | Fabricated edits (new employer, skill, number) were all blocked by the claim guard (block rate 0.5 = exactly the fabricated ones). |
| `llm_interview.new_numbers_unflagged` | **0** | Every number the model invented in a "stronger answer" was flagged to the user. |

## Weaknesses the new suites found, and the fixes

1. **The deep verifier accepted real-but-irrelevant quotes** (first mock run: 3 of 4 posting injections succeeded;
   2 requirements wrongly credited in the gold set). Causes: BLS and ACLS were one skill (a BLS card "proved" ACLS),
   and when a requirement named a skill the quote lacked, any single shared word was enough ("patient **care**" →
   "critical **care**", "**teach** algebra" → "teaching A-level", "200–1,000 **employees**" → "enterprise (5,000+
   employees)"). Fix: BLS / ACLS / PALS are separate skills; a quote must name one of the requirement's skills, or
   share most of its informative words (light stemming; ≥ 2 when a named skill is missing). Locked in by a new
   deterministic `evidence` suite (18 pairs, accuracy 1.0, 0 false accepts). Result: AI-added false credit 2 → **0**,
   system over-credit rate on gold-missing requirements 0.22 → **0.06** (the remainder comes from the rules, not AI).
2. **Prompt leak had no defense**: a resume line asking the model to print its instructions worked. Fix: AI advice
   that repeats a 7-word run of its own instructions is discarded and the built-in advice is shown instead.
3. **AI advice could state unsupported numbers with no warning** (the coach already flagged these; advice didn't).
   Fix: numbers in the advice that aren't in the analysis or resume are shown as a caution under the summary.
4. **Coverage gap (not fixed, reported)**: the engine hands the AI 53 of the 57 gold requirements (`gold_coverage`
   0.93). The 4 missing are licences/languages ("Active RN license", "CPA license", QTS, "Fluent Spanish") that the
   requirement extractor routes to hard-requirement gates, so the deep verifier never judges them.
5. **Test-design correction**: two "planner injection" cases were removed. The planner's input is the user's own
   intent text, so titles the user asks for are honoured by design; titles the *model* invents are measured by
   `llm_planner.off_target_kept_rate` instead.

## Still needs a real model

Quality metrics (`final_accuracy`, `ai_lift`, `hallucinated_quote_rate`, extractor F1, `raw_compliance_rate`,
interview `grade_spearman`, judge `pairwise_accuracy`, consistency) only mean something for a real model. Record them
once per model you use; replays are free afterwards and CI-able. Match-set Spearman/F1/ECE still needs ≥ 300
human-reviewed pairs (60 are queued in Eval Studio → Labelling).
